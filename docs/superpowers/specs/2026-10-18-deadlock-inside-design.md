# Deadlock Inside: архитектура и границы первого релиза

Дата: 18 октября 2026 года. Статус: проект для обсуждения; реализация не начата.

## Цель и подтверждённые решения

Сайт статистики Deadlock по мотивам пользовательских сценариев [Porofessor](https://porofessor.gg/): поиск игрока, оценка результатов и разбор матчей. Пользователь выбрал Next.js и отдельный полноценный бэкенд на Python.

Предлагаемый стек: Next.js App Router + TypeScript, FastAPI + Pydantic, PostgreSQL + SQLAlchemy + Alembic, Redis + Celery, httpx. Один репозиторий, отдельные приложения web и api, отдельные процессы worker и beat. Это предложения плана, кроме уже выбранных Next.js и Python.

## Первый релиз

- Главная: поиск по нику, account ID или Steam ID64. Неуникальный ник возвращает кандидатов; произвольные URL профилей пока не поддерживаются.
- Профиль: имя, аватар, доступный ранг, винрейт, K/D/A, статистика героев, история матчей. Фильтры по периоду и герою.
- Матч: команды, результат, длительность, герои, K/D/A, души, урон и предметы в пределах доступных данных.
- Герои: винрейт, популярность, размер выборки; фильтры по периоду и рангу в пределах возможностей источника.
- Страница героя: агрегаты, противостояния и сборки при подтверждённой доступности полей источника.

Рабочие допущения: русский интерфейс, мобильная версия, публичный просмотр без регистрации. Вне первого релиза: Steam-вход, live-поиск текущей игры, оверлей, прогноз победы, собственный MMR, подписки и импорт реплеев. Эти функции потребуют отдельных планов.

## Источник данных

Кандидат — сторонний [Deadlock API](https://api.deadlock-api.com/docs). Документация просмотрена 18 октября 2026 года; реальные ответы ещё не проверены. Первый этап разработки проверяет поля, поиск, пагинацию, квоты, покрытие истории, условия использования данных и ассетов. Недоступные функции исключаются или пересматриваются до реализации.

Своя база не гарантирует полную историю игрока. Личные показатели относятся к загруженным матчам; глобальные показатели героев берутся из агрегатов источника и маркируются отдельно. Рядом с метриками показываются период, размер выборки, источник и время обновления. Отсутствующие значения — null, а не ноль.

Винрейт = победы / матчи с известным исходом; при пустом знаменателе null. KDA = (сумма убийств + сумма помощей) / max(1, сумма смертей). Не усреднять KDA отдельных матчей.

## Архитектура

```text
Браузер → Next.js → FastAPI → PostgreSQL
                       ↕         ↑
                     Redis    Celery worker → Deadlock API
                                 ↑
                             Celery beat
```

FastAPI владеет предметной логикой и хранилищем. Next.js не обращается к базе напрямую. TypeScript-клиент генерируется из OpenAPI FastAPI. Запросы браузера идут через same-origin proxy, серверный рендеринг — по внутреннему адресу API.

Единый httpx-адаптер нормализует внешние ответы. Worker загружает матчи и обновляет аналитику. Поиск кандидатов допускает короткий синхронный запрос с кешем. Общий Redis-ограничитель учитывает квоты endpoint во всех процессах; ключ API хранится только на сервере.

PostgreSQL хранит игроков, героев, матчи, участников, историю рангов, снимки глобальной аналитики и задания обновления. Redis не является единственным хранилищем результатов. Повторная доставка задач безопасна за счёт upsert, ограничений уникальности и блокировки обновления игрока.

## Контракт API

Префикс `/api/v1`. ID в JSON — строки; время — UTC ISO 8601. В БД ID — BIGINT. Внутренний ID игрока — account ID, Steam ID64 преобразуется после проверки формата. Период: `from` включительно, `to` исключительно.

| Метод и путь | Результат |
| --- | --- |
| GET /health/live | Процесс работает |
| GET /health/ready | PostgreSQL и Redis доступны |
| GET /api/v1/players/search?q=... | До 20 кандидатов |
| GET /api/v1/players/{account_id} | Профиль |
| GET /api/v1/players/{account_id}/stats | Статистика, фильтры from/to/hero_id |
| GET /api/v1/players/{account_id}/matches | История, те же фильтры и cursor/limit |
| POST /api/v1/players/{account_id}/refresh | 202, ID задания |
| GET /api/v1/refresh-jobs/{job_id} | Статус обновления |
| GET /api/v1/matches/{match_id} | Детали матча |
| GET /api/v1/heroes | Справочник |
| GET /api/v1/heroes/stats | Глобальная аналитика |
| GET /api/v1/heroes/{hero_id} | Герой и доступная аналитика |

Статические маршруты объявляются до динамических. История сортируется по started_at DESC, match_id DESC. Курсор содержит обе границы и привязан к фильтрам; limit по умолчанию 20, максимум 100. Неверный ID/курсор/период — 422, отсутствующий сохранённый ресурс — 404. Неполный матч имеет статус partial.

Ответы: data и meta с source, updated_at, sample_size, coverage (partial/unknown), stale; у истории дополнительно next_cursor. Ошибки: `{error: {code, message, request_id}}`, без внутренних исключений. Если профиль ещё не загружен, интерфейс предлагает refresh и повторяет чтение после завершения.

## Обновления, безопасность и эксплуатация

- Refresh игрока повторно использует активное задание и результат последних 5 минут.
- Статусы queued/running/succeeded/failed хранятся в PostgreSQL. Lease и восстановление зависших заданий обязательны.
- Сохранённые задания, не отправленные в брокер, подбирает dispatcher. Повторная доставка не создаёт дубликатов.
- До 3 повторных попыток для временных ошибок; Retry-After при наличии, иначе 5/15/45 секунд. Постоянные 4xx, кроме 429, не повторяются.
- TTL: профили/личные метрики 5 минут, глобальная аналитика 1 час, справочники 24 часа. После записи кеш инвалидируется.
- Beat обновляет глобальную аналитику раз в час, справочники раз в сутки. Игроки обновляются по запросу без обхода всей базы.
- Публичные лимиты: refresh 5/мин и поиск 30/мин на IP. Forwarded IP принимается только от доверенного proxy.
- При сбое источника сохранённые данные доступны с stale=true; без данных — 503. Сбой Redis не разрешает неограниченные внешние запросы.
- Валидация, ограничения времени запросов, структурированные логи с request/job ID, CORS, секреты в окружении, HTTPS на production.
- Docker Compose: web, api, worker, один beat, PostgreSQL, Redis. Наружу доступны только web/reverse proxy.
- Ежедневная резервная копия PostgreSQL с хранением 7 суток; восстановление проверяется в отдельной БД. Хостинг и домен выбираются отдельно.

## Готовность релиза

Из чистого клона доступны документированный запуск и миграции. Работает поиск → профиль → история → матч на реальных данных, аналитика героев показывает размер выборки. Повторный импорт не создаёт дублей. Пустые данные, ошибки и отсутствие ранга обработаны. Проходят API/integration tests, typecheck, Next.js build и браузерный сценарий. Интерфейс проверен на 375 и 1440 px и с клавиатурой. Данные переживают перезапуск, backup восстанавливается.

Версии зависимостей выбираются по совместимости при инициализации и фиксируются lock-файлами. До реализации нужно пересмотреть этот документ вместе с планом; выбор площадки не блокирует локальную разработку.
